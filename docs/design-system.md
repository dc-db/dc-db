# dc-db 界面设计规范

本规范面向维护资产、网络和机房的桌面端运维人员，目标是在持续迭代时保持界面可预测、信息清晰、操作安全。新增界面和修改现有界面时遵循本规范；已有页面不要求为符合规范而集中重写，应在涉及对应功能时逐步收敛。

规范描述的是新改动的目标，不代表现有页面、组件或所有颜色已经完全符合。规范与实际实现不一致时，先确认是否需要调整规范或公共实现，不要在业务页面复制另一套规则。

## 设计原则

1. **先完成任务，再装饰界面**：常用信息和主要操作应容易找到；同一类页面使用一致的布局和操作位置。
2. **适合桌面运维**：允许适度的数据密度和横向空间，避免为移动端牺牲表格效率。窗口缩小时保证主要操作和内容仍可使用。
3. **明确状态和后果**：加载、空数据、无结果、失败、无权限和成功各有清楚反馈；涉及批量或不可逆操作时说明影响范围。
4. **复用优先**：先使用已有基础组件和主题变量；相同需求出现在多个页面时，优先提炼共享业务组件，而不是复制页面实现。
5. **保护资产数据**：示例、截图和测试使用虚构数据或文档专用地址，不在仓库保存真实企业数据。

## 组件与主题的来源

- 基础组件使用 `web/src/components/ui/` 中的 shadcn/ui 组件；图标使用 Lucide。需要新增基础能力时，先检查已有组件，再按项目现有方式引入或扩展。
- 当前通用颜色变量定义在 `web/src/styles.css` 的 `:root` 和 `html[data-theme="dark"]`；`web/src/shadcn.css` 将这些变量映射到 shadcn/Tailwind 语义颜色并定义圆角。业务页面优先使用这些语义变量或工具类，不要再定义平行的全局颜色体系。
- 当前主要语义包括页面背景 `--bg`、表面 `--surface`、正文 `--text`、次要文本 `--muted`、边框 `--line`、主色 `--primary`、弱背景 `--subtle`、悬停 `--hover` 和选中 `--selected`。表面、文字和边框要按语义组合，不能假设某个固定色值适用于两种主题。
- 中性色是界面的基底：页面、卡片、表格、侧栏和主要按钮保持黑、白和灰阶；蓝色、绿色、琥珀色和红色只作为状态、选中、链接或图表的强调色，不用于大面积背景。当前强调语义为 `--info`（信息/链接/选中）、`--success`（在线/运行/成功）、`--warning`（暂停/预留）、`--danger`（离线/错误/破坏性操作），并成对提供 `-soft` 和 `-border` 浅底色与边框值。图表使用 `--chart-1` 到 `--chart-5`。
- 系统首次访问跟随系统主题；用户选择保存在 `localStorage` 的 `dc-db-theme`，通过 `html[data-theme]` 应用。新增样式必须兼容现有机制，不另建主题开关或另存一份主题状态。
- 状态色、图表色和部分业务样式目前仍有局部硬编码。新需求需要可复用的状态或图表色时，优先使用已定义的强调 token，并同时检查浅色、暗色；新增 token 要在 `styles.css` 中成对定义，再接入使用处，不要在业务页面复制色值。
- 机柜和机柜立面使用现有 `--floor-*`、`--rack-*`、`--device-*` 等专用变量；ECharts 中无法直接使用 CSS 变量的地方，应从同一语义来源取得或集中映射颜色，并检查两种主题。
- `AppControls.tsx` 目前承载部分现有页面的兼容封装；`SearchableSelect.tsx` 提供可搜索选择。新页面优先直接组合基础组件或复用合适的共享业务组件，修改现有页面时避免无必要扩大兼容封装；不要假设所有页面已经共用同一个数据表格。

## 视觉基础

品牌图形、字标、GitHub 素材和最小尺寸遵循[品牌标识](brand.md)，系统统一通过 `Wordmark.tsx` 使用，不在业务页面重画 logo。

### 布局与层级

- 页面保持「导航与标题 → 筛选和主要操作 → 内容 → 分页或后续操作」的顺序；同一类型页面的主要操作放在一致位置。
- 优先采用左对齐、清晰分组和足够留白。卡片用于区分独立内容区域，不为每个字段或每行数据重复套卡片。
- 间距以 4px 为基础，优先使用 4、8、12、16、24、32px；相同层级使用相同间距，页面局部有特殊需求时说明原因。
- 基础圆角沿用 `shadcn.css` 的 6、10、14px 阶梯；表格容器等需要更紧凑的局部容器可使用 8px。相同控件保持同一圆角，不因页面不同随意变化。
- 字号保持清楚的页面标题、区块标题、正文和辅助信息层级；正文和表格默认以约 14px 为起点，辅助信息通常不小于 12px。使用项目现有字体栈，资产名、地址、数值等按内容展示；IP、CIDR 和其他需要逐字符辨识的值可用等宽字体。
- 优先使用现有语义色和组件变体。主色用于主要操作，信息色用于链接和选中，成功、警告、危险和中性状态应有稳定语义，不以颜色数量代替信息层级。

### 主题与对比度

- 两种主题都要检查默认、悬停、聚焦、选中、错误和禁用状态。文字颜色要与实际背景组合检查；不能只检查 token 本身。
- 以 WCAG 2.2 AA 为新改动的验收目标：普通文字对比度至少 4.5:1，大文字至少 3:1；识别控件、状态和理解图形所必需的非文本信息，按适用条件检查至少 3:1。禁用控件等例外依标准判断。
- 状态不能仅靠颜色区分：同时使用文字、图标、形状或图例。例如显示「在线」「离线」，而不只显示绿点、红点。
- 此规范不宣称当前产品已通过 WCAG 审计；发现历史颜色对比不足时，在涉及该组件的修改中修复并复测两种主题。

## 常用交互

### 按钮与操作

- 每个操作区域突出一个主要操作；次要操作用次级或描边样式，危险操作用明确的危险语义。按钮文案使用动词，例如「新增资产」「保存」「删除」。
- 纯图标按钮必须有可访问名称；含义不够直观时增加可见文字或提示，不依赖颜色传意。

### 按钮状态（视觉基线）

- 主按钮 `default`：`--primary` 实底；悬停降到 90% 不透明度。
- 次要按钮 `outline`：1px `--line` 边框 + 页面底色。浅色悬停用 `--hover`（#f5f5f5）；深色悬停用 **10% 白色叠加**，边框提到 30% 白，文字转为纯白。
- 幽灵按钮 `ghost`：无边框；深色悬停用 8% 白色叠加。
- 危险操作使用 `destructive` 变体，只在删除、释放等不可逆动作上出现。
- 焦点态：3px 半透明 `--ring` 描边，键盘可见即可，不长期显示。
- 禁用态：50% 不透明度并禁用指针事件；不要用灰色文字代替禁用态。
- 尺寸：`sm` 高 32px，`default` 高 36px；图标 16px，图标与文字间距 6px。
- 工具条等密集区域统一 `sm`，同一行按钮保持同一变体与高度，主动作放在最右。
- **悬停必须可感知**：深色下白色叠加不低于 8%，浅色下用 `--hover`；只改文字颜色或只改 2% 背景的做法视为不合格。
- 按钮内的箭头方向遵循操作方向：导入（数据进入）用向下进托盘，导出（数据离开）用向上出托盘。
同一区域的视图切换使用分段控件：浅色轨道上放当前项的实心胶囊，选项用简短名词（如「列表」「立面图」），不要用一排孤立的图标按钮。异步操作期间显示进行中状态并防止重复提交，失败后允许重试。
- 非破坏性的取消、关闭不弹确认；删除、释放和其他不可逆操作，在确认框中写明对象、影响和结果。批量操作必须显示所选数量，并明确影响当前页还是跨页选择。
- 权限由服务端最终校验。无权限时不展示不适用的写操作，或提供明确的只读说明；不要仅依靠前端隐藏实现权限控制。

### 表格与列表

- 数据表使用原生表格语义，按需组合 `ui/table` 和 TanStack Table；列定义、格式化与业务操作留在业务层，排序、分页、选择和通用状态优先复用共享实现。
- 同类表格统一标题、筛选区、操作区、表头、空状态和分页位置。排序列应能通过视觉和可访问状态识别方向；点击排序时使用稳定的字段语义。
- 分页支持总数和当前页提示，常用页大小为 10、20、50；资产列表默认 10 条，其他页面可根据内容密度沿用现有默认值。记录用户偏好的页面应保持该偏好。
- 必须明确排序、筛选和选择作用于全量结果还是当前页。服务端分页时，涉及全量的筛选或排序应由服务端处理，不能将当前页排序表现成全量排序；筛选条件变化时将页码调整到有效范围。
- 跨页选择必须保留已选项并显示总数；清除筛选、切换页面大小、执行批量操作后的选择行为应明确且可预测。权限不足时不提供可提交的批量操作。
- 区分「尚无数据」与「筛选无结果」；前者可提示如何新增，后者提供清除或调整筛选的办法。加载、失败、无权限不能伪装成空列表。长文本允许截断，但要提供完整内容的可访问方式。

### 表单、弹窗与反馈

- 表单输入项有持久可见且关联的标签，必填、单位、限制和格式在输入前可见；占位文字只作示例，不代替标签。表格筛选或分页跳转等紧凑控件至少提供可访问名称，需要解释用途时增加可见标签。错误提示靠近字段并说明如何修正。
- 保持已输入内容，除非保存成功、用户主动取消或明确选择重置。异步保存时禁用重复提交；服务端校验错误应可见且不丢失表单内容。
- 列表筛选可即时生效；复杂或批量修改在提交前提供清晰的确认动作。CSV 导入必须保留预检、错误说明和整批成功或失败的语义。
- 对话框和抽屉提供可访问标题；打开后焦点进入其中，Tab 循环受限于弹窗，关闭后焦点返回触发位置。默认支持 Escape 关闭；正在提交或存在未保存更改时，根据操作状态防止意外丢失。
- 成功可用简短消息反馈；需要用户处理的错误应保留在当前页面或表单中，不只依赖自动消失的提示。

### 数据中心、机柜与图表

- 机柜表格和机柜立面应使用同一份业务数据，视图切换、设备选择和定位保持一致。
- 机柜立面中，装在当前查看面的设备用状态色实心条；只能隔着机柜看到的对面设备用 45° 斜纹（`#f7f7f7` 底 + `#ffc0c0` 条纹 + 深色文字）。浅色与深色主题都用这套浅色斜纹，保证在暗色界面上同样醒目。前后面、U 位和安装深度要以文字或图例解释，不能只靠颜色。
- 拖动应有明确的可放置、不可放置和忙碌反馈；提供表单或其他不依赖拖动的等效操作，并保留服务端的冲突和越界校验。
- 图表应包含标题、单位及必要的图例，提供可通过文字或表格理解的关键数值；空数据、加载失败和图形不可用时给出清楚说明。不得在演示图表中嵌入真实资产数据。

## 组件演进顺序

1. 先查找 `ui/`、`SearchableSelect` 和现有业务组件；已有能力足够时直接复用。
2. 重复出现的分页、筛选栏、空状态和表单反馈，优先抽出可组合的共享组件；业务列、接口、权限和领域校验留在业务层。
3. 将散落的状态色和图表配色逐步迁入主题语义，浅色和暗色一起调整；不为一次性差异建立全局 token。
4. 过渡期允许旧页面使用现有封装。改动时保持功能和视觉一致，逐步收敛；抽象尚不稳定时不强制所有页面共用同一实现。

## 修改前后的检查

- 明确受影响页面、权限角色、加载/空/错误/成功状态，以及是否涉及筛选、分页、批量操作或未保存内容。
- 检查浅色和暗色，覆盖正文与背景、表格、弹窗、表单、图表或机房视图的实际组合；不要只看登录或首页。
- 使用键盘检查焦点顺序、可见焦点、选择器及弹窗开关；验证图标按钮名称和必要的表格、表单语义。
- 在常见桌面窗口及较窄桌面窗口检查溢出、横向滚动和关键操作可达性；不要求移动端布局。
- 用虚构数据验证受影响的主要流程及权限；前端代码改动运行 `npm --prefix web run check`，涉及打包运行 `npm --prefix web run build`。按仓库约定完成其他适用检查与交付。

## 实现基线（当前代码的实测值）

下面是当前实现采用的数值，新增页面和改版照此取值，不要在业务页面临时发明新数值。

### 间距与尺寸

| 项目 | 值 | 位置 |
| --- | --- | --- |
| 顶栏高度 | 56px | `.app-header` |
| 内容区内边距 | 14px 24px 24px | `.app-content` |
| 应用侧栏宽度 | 200px | `--sider-width` |
| 数据中心树面板 | 260px，可拖动 180–420px | `.facility-layout`、`.facility-resizer` |
| 面板分隔线 | 2px，`--line` 常驻，悬停加深为 `--muted` | `.facility-resizer::after` |
| 卡片圆角 | 12px | 页头卡片、机柜卡片 |
| 页头卡片内边距 | 10px 16px | `.dc-summary` |
| 统计列宽 | 140px/列，左内边距 22px | `.dc-stat` |
| 表格单元格 | 10px 12px | `.facility-table` |

间距只用 4 的倍数和少量 6/10/14：4、8、10、12、14、16、24。页面级留白用 24，区块之间用 12–16，控件内部用 6–10；同一层级保持一致，需要偏离时在代码注释里写明原因。

### 字号层级

| 用途 | 字号 / 字重 | 示例 |
| --- | --- | --- |
| 页面标题 | 24px / 600 | 数据中心名称 |
| 区块标题 | 18px / 600 | 侧栏「数据中心」 |
| 表格表头 | 12px / 500，`--muted` | 机柜、U 位总数 |
| 正文 | 13–14px | 列表内容、表单字段 |
| 辅助信息 | 12px，`--muted` | 区域名、单位说明 |
| 关键数字 | 24–26px / 600，`font-variant-numeric: tabular-nums` | 机柜 3、利用率 6% |

### 图标

- 统一使用 Lucide，行内默认 16px；纯图标按钮必须同时提供 `aria-label` 和 `title`。
- 语义固定，不随手换：数据中心 `Building2`、立面图 `Columns3`、表格视图 `List`、新增 `Plus`、更多 `MoreHorizontal`。
- 图标是单色线条，不加彩色圆底、不加渐变底色。

### 反「AI 味」规则

- 不用大面积渐变、彩色光斑和霓虹色。登录页允许一层极淡的品牌色光晕，其余页面保持中性。
- 强调色（`--info`、`--success`、`--warning`、`--danger`）只用于状态、选中和链接，不做装饰。
- 不堆叠「彩色圆底 + 图标」的徽章，数字用字号和字重表达层级。
- 文案去重：标签已经说明含义时不再重复单位，写「机柜 3」而不是「机柜数 3 台机柜」。
- 同一行里不要同时出现标题、副标题和装饰图形；标题足够的场景不加副标题。

### 组件边界

- 基础控件来自 shadcn/ui（Radix + Tailwind），数据表格的排序、分页、选择来自 TanStack Table；`AppControls.tsx` 只是兼容层，不承载新的设计决策。
- 业务页面不写全局样式；一次性的布局调整放在页面级 class（如 `.facility-*`、`.dc-*`），可复用的颜色和间距先进 `styles.css` 变量或公共 class。
- 新增颜色必须是 `styles.css` 中成对定义的语义变量，并同时检查浅色与深色。
- 覆盖 shadcn 组件默认值时（例如卡片内边距），只针对该业务的 class 覆盖，不改 `components/ui/` 里的共享组件。
